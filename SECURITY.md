# Security Policy

## Reporting a vulnerability

If you discover a security vulnerability in any Clarvia repository, **do not open a public issue**. Instead, report it privately:

📧 **security@clarvia.org**

Include:

- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)

## Response timeline

| Step | Target |
|---|---|
| Acknowledgement | Within 48 hours |
| Initial assessment | Within 5 business days |
| Fix or mitigation | Depends on severity |
| Public disclosure | After fix is deployed |

## Scope

This policy covers all repositories under the [clarvia-org](https://github.com/clarvia-org) GitHub organisation.

## Data accuracy as a safety concern

Clarvia publishes legal deadlines and procedural obligations that families rely on during bereavement. **Incorrect data can cause real harm** — missed deadlines, financial penalties, or legal complications.

If you discover an inaccuracy in workflow data that could cause harm, treat it with the same urgency as a security vulnerability and report it to security@clarvia.org.

## Supported versions

We support the latest published version of each repository. Older releases do not receive security updates.
